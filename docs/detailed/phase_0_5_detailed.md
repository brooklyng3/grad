## 3. Ground Truth Acquisition: `mirai_labels.csv`

### 3.1. Retrieval Command
Downloaded the official per-packet binary ground truth vector from the Kitsune benchmark repository:
```bash
curl -s -L "https://raw.githubusercontent.com/zyyrrr/attack-defense/master/mirai_labels.csv" -o data/raw/mirai_labels.csv
```

### 3.2. Label Vector Diagnostics & Line-Ending Audit
- **Path:** `data/raw/mirai_labels.csv`
- **File Size:** `2,292,409 bytes` (~2.3 MB)
- **Encoding:** ASCII text (`0` for benign, `1` for malicious)

#### Line Count Discrepancy Investigation:
Initial check using `wc -l` reported:
```bash
wc -l data/raw/mirai_labels.csv
# Output: 764136
```
To investigate the 1-count difference against the `764,137` packets, a hex dump of the EOF bytes was executed:
```bash
tail -c 20 data/raw/mirai_labels.csv | xxd
# Output: 0a31 0d0a 310d 0a31 0d0a 310d 0a31 0d0a 310d 0a31 (terminates with byte 0x31 '1' without trailing 0x0a)
```
**Conclusion:** Linux `wc -l` counts newline characters (`0x0A`). Because the final line ends at EOF without a terminating `\n`, `wc -l` under-reported by 1.

#### Verification via Python Parser:
```bash
python3 -c "
with open('data/raw/mirai_labels.csv', 'r') as f:
    entries = [line.strip() for line in f if line.strip()]
print('Total label entries:', len(entries))
"
# Output: Total label entries: 764137
```
**Confirmed:** Exactly `764,137` ground-truth labels exist, matching `mirai.pcap` at 100% 1-to-1 parity.

## 4. High-Performance Packet Dissection (`mirai.pcap.tsv`)

### 4.1. Extraction Execution
Dissected packet fields into a tab-delimited intermediate file according to `Kitsune-py/FeatureExtractor.py` specification:

```bash
/usr/bin/tshark -r data/raw/mirai.pcap -T fields \
  -e frame.time_epoch \
  -e frame.len \
  -e eth.src \
  -e eth.dst \
  -e ip.src \
  -e ip.dst \
  -e tcp.srcport \
  -e tcp.dstport \
  -e udp.srcport \
  -e udp.dstport \
  -e icmp.type \
  -e icmp.code \
  -e arp.opcode \
  -e arp.src.hw_mac \
  -e arp.src.proto_ipv4 \
  -e arp.dst.hw_mac \
  -e arp.dst.proto_ipv4 \
  -e ipv6.src \
  -e ipv6.dst \
  -E header=y -E occurrence=f > data/raw/mirai.pcap.tsv
```

### 4.2. Output Profile & Validation
- **Path:** `data/raw/mirai.pcap.tsv`
- **File Size:** `94 MB` (98,565,302 bytes)
- **Total Lines:** `764,138` (1 column header row + `764,137` packet data rows)
- **Header Line:**
  ```text
  frame.time_epoch	frame.len	eth.src	eth.dst	ip.src	ip.dst	tcp.srcport	tcp.dstport	udp.srcport	udp.dstport	icmp.type	icmp.code	arp.opcode	arp.src.hw_mac	arp.src.proto_ipv4	arp.dst.hw_mac	arp.dst.proto_ipv4	ipv6.src	ipv6.dst
  ```
- **Execution Performance:** Completed in `72 seconds` utilizing a single CPU core with $< 250$ MB RAM footprint.

## 5. Architectural Separation of Data Tiers
A critical finding confirmed during this phase:
- `data/raw/mirai.pcap.tsv` represents **raw packet metadata** (strings, MACs, IP addresses, ports). It is **not** a numeric feature file.
- The 100-dimensional continuous statistical feature vectors must be generated by streaming this file through `AfterImage` (`FE.get_next_vector()`).
- In Phase 1.5, these 100D numeric features will be stored in `data/processed/mirai_features.npy` as a memory-mapped `[764137, 100]` `float32` matrix, completely isolating raw packet strings from neural network training and evaluation pipelines.
